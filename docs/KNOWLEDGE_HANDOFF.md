以下は既存アプリから得た知見です。新しい端末で再確認し、Hogo Panel の実装判断に使います。既存アプリのソースや APK はこのリポジトリに複製していません。

## 端末と開発環境

- 動作実績は Android 化した Echo Show 5、LineageOS 18.1、Android 11（API 30）、960×480 の横画面です。他世代や標準 OS での動作実績ではありません。
- 既存のビルド環境は JDK 17、compileSdk / targetSdk 35、minSdk 30、Android Gradle Plugin 8.7.3、Kotlin 2.1.0、Gradle 8.11.1 です。新アプリの採用版を確定する際は互換性を確認します。
- 960×480 を配置の基準とし、実際の View の大きさから縦横比を保って拡大・縮小します。文字とタップ領域、時計の移動余白を同じ座標設計で扱います。
- Kotlin と Android 標準 View / Canvas で、固定画面の描画とタッチ操作を実装できました。新アプリでも候補になりますが、UI 技術はまだ確定していません。

## 全画面と常設起動

- 既存アプリは `FLAG_KEEP_SCREEN_ON` で前面表示中の点灯を維持し、`WindowInsetsController` でシステムバーを隠します。端からのスワイプでは一時的にバーを表示できます。
- `BOOT_COMPLETED` と `MY_PACKAGE_REPLACED` を契機に起動し、HOME アプリの候補としても登録しています。
- Android 10 以降のバックグラウンド起動制限を考慮し、既存環境では HOME の指定、または「他のアプリの上に表示」の許可を使用しました。Manifest の宣言だけで自動起動が保証されるわけではありません。
- スワイプ式ロック画面の前面には表示できました。PIN 等のロック解除は利用者が行います。
- 新アプリの applicationId は既存の `io.github.ysogabe.miharashi.panel` と分けます。HOME の変更は端末全体に影響するため、導入時に対象端末を確認します。

## 待機・復帰と誤操作防止

- 以前の「自動消灯」は、低輝度の時計表示に置き換えました。画面自体を OFF にすると時計は表示できません。
- 待機までの経過時間には `SystemClock.elapsedRealtime()` を使い、表示する時刻には現地時刻を使います。端末の時刻補正で待機時間やアニメーションが飛ばないよう分けます。
- 時計からの最初のタッチは復帰専用です。指を離すまで一連のジェスチャーを消費し、背後の記録ボタンへ伝えません。お世話記録の誤送信を防ぐため、新アプリでも必須です。
- 明るさはウィンドウ単位で変更し、復帰時はシステム設定に戻します。時計の詳細は [IDLE_CLOCK.md](IDLE_CLOCK.md) を参照してください。

## ライフサイクルと通信

- 既存アプリでは `onResume` で同期を開始し、`onPause` で停止します。描画の予約・アニメーション・ネットワークコールバックも前面状態に合わせて解除します。
- 停止した同期処理から遅れて届いた結果を、新しい画面状態へ反映しない作りにします。接続先や認証情報が変わったら、以前の接続先の状態を捨てます。
- 最後に取得した状態と取得時刻を持ち、Wi-Fi 接続と API の疎通・鮮度を区別します。通信失敗を成功や最新情報として表示しません。
- 既存アプリでは SSE と定期取得を併用しましたが、これは Miharashi の API に合わせた方式です。hogo-meter に SSE が存在するとは扱わず、正式な連携方式を確認します。
- 記録 POST がタイムアウトした場合は、サーバーに届いた可能性があります。冪等性の仕組みを確認せず自動再送せず、重複記録を避ける方針とします。
- 接続情報をソースに埋め込まず、端末設定として管理します。既存の LAN 用 HTTP 許可や Bearer 認証を hogo-meter へそのまま持ち込みません。

## ビルドと端末導入

以下は既存アプリでの手順です。本リポジトリにはまだ `gradlew`、`scripts/install.sh`、APK はありません。

```sh
# 既存の miharashi-panel 内での検証・ビルド
./gradlew testDebugUnitTest assembleDebug

# 接続端末の確認。複数台ある場合は adb -s <serial> で対象を指定する
adb devices -l
```

- debug APK の標準出力先は `app/build/outputs/apk/debug/app-debug.apk` です。
- 既存の導入スクリプトは上書きインストール、起動用権限の設定、起動に対応しています。新アプリへ流用する場合はパッケージ名を変更し、対象端末の選択にも対応させます。
- `run-as` による設定注入は debug ビルド用です。トークンはファイルから標準入力で渡し、コマンド行やログへ値を出さない方式でした。
- SDK パスの `local.properties`、鍵、トークン、署名設定、APK、ビルド出力はコミットしません。

## 確認済みの範囲と残る検証

既存の時計変更では、2026-10-17 に `testDebugUnitTest assembleDebug` が成功し、単体テスト61件（時計関連の新規24件を含む）が失敗・エラーなしでした。既存の Echo Show 5 へ適用後、起動、接続表示、無操作3分での時計切替、画面内に収まる表示、最初のタッチでメニューを開かずに復帰する動作を確認した記録があります。利用者の実機動作承認も記録されています。

5%指定時の実際のバックライト輝度はスクリーンショットでは検証できません。長時間表示での残像・消費電力・新端末での読みやすさは別途確認します。この実績を Hogo Panel のテスト結果として転記してはいけません。

新アプリでは時刻境界、時刻補正、待機設定0分、復帰ジェスチャー、バックグラウンド停止、通信切断と認証期限切れ、記録の二重送信を検証します。実機ではさらに再起動後の起動、画面の欠け、操作音・振動、時計の連続動作を確認します。
