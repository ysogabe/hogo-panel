# 消灯時・無操作時の時計表示仕様

引き継ぎ日: 2026-10-18。Hogo Panel で採用する待機表示の仕様です。

## 実装状況

**0.1.0（時計のみの PoC）:** 起動直後から時計だけを表示します。「画面」と「明るさ・移動・更新頻度」の各項目（`HH:mm`、基準 960×480、移動・濃淡、450ms のフリップ、補正時の即時合わせ、`onPause` での描画予約停止、ウィンドウ輝度 0.05f、keep screen on、全画面・横向き）を実装し、時計のみの実機確認を [BUILD.md](BUILD.md#実機検証結果2026-10-18) に記録しています。

**0.2.0（架空データの操作モック）:** 時計の前段に操作画面（[画面設計](routine-ui/design.md#android-操作モック)）を置き、次を実装しました。単体テストに加え、Show 5実機でADB入力による主要遷移・3分待機・輝度指定と復帰を確認済みです。人の指の境界操作や肉眼の読みやすさは未確認です（[検証記録](routine-ui/verification.md)）。

- 無操作の測定と時計への切替（固定3分。`SystemClock.elapsedRealtime` による経過時間）。設定画面・「時計表示まで」の設定値・0分の無効化は未実装です。
- 時計ボタンによる手動切替。時計は既存の `FlipClockView` をそのまま使い、アンチ焼き付きの移動・濃淡・分の反転は変えていません。
- 時計の最初のタッチ（またはキー・戻る）はホームへ戻るだけで、全ての指の UP/CANCEL まで消費します。タイムアウトに達しタイマーがまだ走っていない瞬間のタッチも復帰として扱います。指が触れている間は時計へ切り替えず、離した操作で待機時間を数え直します。マルチタッチのジェスチャーは操作になりません。
- 警告期間だけ、時計の下に対象薬名の琥珀色の札を添えます（説明・日付・件数なし）。札は時計と一緒に動きます。
- 時計中だけウィンドウ輝度を指定。0.2.2 から時間帯別（下記）で、0.2.1 までは固定 0.05。ホームでは `BRIGHTNESS_OVERRIDE_NONE` に戻します。
- `onPause`・View の破棄で、時計の描画予約と全タイマーを止めます。`onResume` はホームを表示し、待機時間を数え直します。

HOME 指定・自動起動・新しい権限は追加していません。記録操作を外部へ送る処理もありません（メモリ内のみ）。

**0.2.1:** 当日・未確認の薬カードだけがホームで明滅するようになりましたが、時計・時計の札・コロンは静止のままで、点滅・濃淡の周期は上記の既存のとおりです（[明滅の仕様](routine-ui/design.md#当日超過の明滅021)）。時計の間は明滅の予約を止め、時計の更新頻度（約1秒）も変わりません。

**0.2.2:** 常設の時計として使えるよう、時計中のウィンドウ輝度を現地時刻の3つの時間帯で切り替えます（承認済み）。深夜は従来の0.05のままで、色・数字・濃淡・形・薬名の札は変えていません。

| 現地時刻 | 時間帯 | `screenBrightness` |
|---|---|---|
| 06:00 以上 18:00 未満 | 日中 | 0.60 |
| 18:00 以上 22:00 未満 | 夜 | 0.20 |
| 22:00 以上、または 06:00 未満 | 深夜 | 0.05 |

- 判定は端末の現在の壁時計とタイムゾーン（時計の表示と同じ）で行い、モック投薬の日付には依存しません（純 Kotlin の `ClockBrightness`）。
- 時計に入ったとき（手動・3分待機）と、前面復帰後に時計を出し直したときに評価し直します。時計を出し続けても、`ClockBrightnessKeeper` が分の境界（＋20ms）ごとに評価し直すので、6・18・22時を越えれば自動で変わり、時刻・タイムゾーンの補正にも1分以内に追従します。専用の receiver・権限・サービスはなく、前面で時計が出ている間の Handler 予約だけです。待ち時間は相対値で、時間帯の判定には使いません。
- 値が変わらない評価では WindowManager を更新しません。描画のフレーム数も増やしません。
- ホームへの復帰・時計の終了・`onPause`・View の破棄では予約を解除して `BRIGHTNESS_OVERRIDE_NONE` に戻します。解除後に古いコールバックが届いても再予約しません。時計を出し直しても予約は1つです。
- 設定画面・プレビュー・永続保存は追加していません。端末全体の明るさ・自動調光・時刻・タイムゾーンは変更しません。HOME 登録・自動起動もしていません。

## 「消灯」の意味

ここでいう消灯時表示は、無操作時に通常のパネルを低輝度の時計へ切り替えることです。バックライトと画面を完全に OFF にするものではありません。モニター等の外部機器の消灯状態とも独立しています。

出典は Miharashi Panel の [承認済み時計仕様](https://github.com/ysogabe/miharashi-panel/blob/93f28431fcb74b6f19b1dc4dca37b34c2e26d7af/docs/IDLE_CLOCK.md) と、その時点の [FlipClock.kt](https://github.com/ysogabe/miharashi-panel/blob/93f28431fcb74b6f19b1dc4dca37b34c2e26d7af/app/src/main/java/io/github/ysogabe/miharashi/panel/FlipClock.kt) です。Miharashi 用の操作送信は、お世話記録の操作へ読み替えます。

## 画面

- 横向きの全画面。黒背景、暗いカード、明るさを抑えたグレーの数字。
- 端末の現地時刻を24時間制の `HH:mm` で表示。先頭の0を表示します。秒、日付、ロゴ、常設の復帰案内は表示しません。コロンは点滅させません。
- 960×480 を基準に時計全体は約626×216。数字カードは1枚140×216、同じ組内のカード間隔9、中央のコロン領域48です。
- 表示領域に合わせて縦横比を維持して拡大・縮小し、移動しても画面端から欠けない範囲に収めます。
- 通常の分の切り替わりでは、変わった桁だけ約450msでフリップします。上半分が手前へ倒れ、下半分へ落ちる動きを、上下別の描画と継ぎ目・陰影で表現します。
- 初回表示、待機への切替直後、前面復帰、時刻やタイムゾーンの大きな補正では現在時刻を直接表示します。停止中の分を連続再生しません。

## 待機条件と設定

- 無操作の初期値は3分。設定名は「時計表示まで」、範囲は0〜240分、0は無効とします。
- 操作画面のタッチで待機時間をリセットします。API の応答や画面更新は利用者の操作として数えません。
- 待機時間は単調増加する経過時間で測定し、現地時刻の補正に影響されないようにします。
- 既存アプリの設定キーは `sleep_minutes` です。新アプリでも使う場合は単位と0の意味を維持します。別アプリのため既存設定が自動移行するわけではありません。

## 遷移とタッチ

1. 操作画面で無操作時間に達したら、低輝度時計へ切り替えます。
2. 時計のどこかに触れたら、操作画面と通常の明るさへ戻します。
3. 復帰に使ったジェスチャーは、指が離れるかキャンセルされるまで全て消費します。記録・取り消し・画面遷移などの操作へ流しません。次の独立したタッチから通常操作を受け付けます。
4. タイムアウト到達後、描画がまだ時計に切り替わっていない瞬間のタッチも復帰扱いにします。ボタンを誤って送信しないため、描画状態だけで判定しません。
5. 設定画面から戻る場合を含め、`onResume` では操作画面を表示し、待機時間を数え直します。
6. `onPause` と View の破棄時には描画更新・アニメーションの予約を止めます。前面復帰では現在時刻へ合わせます。

時計表示中もアプリが前面にいる間は、採用する連携方式に従って状態を同期します。記録操作は発生させません。背面中の同期方法は別途設計します。

## 明るさ・移動・更新頻度

- 待機中の `WindowManager.LayoutParams.screenBrightness` は、0.2.1 までは固定 0.05f でした。0.2.2 以降は上記の時間帯別（深夜が 0.05f）です。復帰時は `BRIGHTNESS_OVERRIDE_NONE` へ戻し、端末全体の明るさ設定は変更しません。
- 時計全体（カード・数字・コロン）を緩やかに移動します。基準画面で中央から左右最大48、上下最大32。実際の画面サイズと余白に合わせて上限を小さくします。
- 既存実装の移動周期は水平方向317秒、垂直方向211秒。濃淡の周期は463秒、係数は0.86〜1.00です。滑らかに変化する関数を使い、突然位置を飛ばしません。
- 通常の待機描画は約1秒ごととし、分の境界にも更新を予約します。既存実装の境界余裕は20msです。フレーム単位の更新はフリップ中だけ行います。
- 表示時刻は壁時計とその時点のタイムゾーン、フリップの進行と移動は経過時間を使います。既存実装は両者の進みの差が2秒を超える場合を時刻補正として扱います。
- 夜間の時刻に応じた減光は、元の引き継ぎ仕様には含まれません。0.2.2 で、承認を得て上記の3段階だけを追加しました（設定画面での変更は未対応）。

低輝度と移動は残像リスクを下げるための配慮です。焼き付き防止を保証しません。0.05などのウィンドウ指定値と、実際の輝度・消費電力は区別します。

## 受け入れ時の確認

- 初期値3分で時計に切り替わり、0分では切り替わらないこと。設定の範囲と保存・再起動後の読み込みを確認すること。
- `09:59 → 10:00`、`23:59 → 00:00`、日付・タイムゾーン変更、時刻の前後補正でも正しい4桁を表示すること。
- 通常の分の変化だけで該当桁がフリップし、初回・前面復帰・大きな補正で連続アニメーションしないこと。
- 記録ボタン位置を触って復帰しても、記録 API が送信されないこと。複数の指、移動、キャンセル、タイムアウト境界も確認すること。
- 前面復帰で待機時間をリセットし、背面・破棄後に描画予約が残らないこと。
- 新端末の実際の表示領域で移動時も欠けず、復帰時に明るさが戻ること。最低輝度での肉眼の読みやすさと長時間の残像は実機で確認すること。

既存アプリでは基本表示、自動切替、復帰の実機確認と利用者承認の記録があります。Hogo Panelでは時計のみの基本表示（0.1.0）に加え、0.2.0の3分待機、警告名の札、最初の復帰タッチ、背面からホームへの復帰を実機で確認しました。輝度は0.2.0でのWindowManagerの指定0.05とホームでの指定解除を確認したもので（過去の確認として残します）、バックライトの実測ではありません。0.2.2では夜の0.20とホーム・背面での解除、時計への再適用を実機で確認しました。各時間帯・境界・時刻補正の追従は単体テストで検証し、実時刻での境界通過は未検証です。スクリーンショットの画素ではバックライト輝度を測れません。複数指・連打・境界は単体テスト、人の指・肉眼の低輝度・残像は未検証です。待機設定（範囲・保存・再起動後の読み込み）は未実装です。
