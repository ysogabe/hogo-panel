# 環境光による自動輝度・描画コントラスト（0.6.0）

ホーム・確認・シナリオ選択・時計を含むアプリ全画面で、内蔵照度センサー `SensorManager.TYPE_LIGHT` の値に合わせて `window.attributes.screenBrightness` を指定します。前面かつ View が接続されている間だけ購読します。システムの輝度値・自動調光モードは変更せず、`WRITE_SETTINGS` などの権限も追加しません。操作・配置・API の取得は変えず、描画の色を照度に応じて補間します。

## 設計値

| 照度（lux） | ウィンドウ輝度 |
|---|---|
| 0 | 0.05 |
| 5 | 0.10 |
| 20 | 0.20 |
| 100 | 0.40 |
| 300 | 0.60 |
| 1000以上 | 0.85 |

各点の間は lux に対して線形に補間します。常に 0.05〜0.85 で、暗闇でも画面を消しません。これはバックライトの実測輝度ではなく Android へ渡す指定値です。

- 前面セッションで初めて有効な照度を受けた時だけ即時に適用します。直前のシステム輝度は読み取りません。
- 以後は、補間後の値と前回採用した目標の差が **0.02以上** のときだけ目標を更新します。微小な揺れではウィンドウを更新しません。
- 目標変更後は **250ms** ごとに最大 **0.025** ずつ増減し、最後は目標値に合わせて予約を止めます。0.05から0.85まではおおむね8秒（メインスレッドの遅延を除く）。途中で新しい目標を受けても待機時間を延ばさず、同時予約は1つです。
- センサーが on-change でも、追加イベントなしで目標へ到達します。到達後は輝度用タイマーを止め、有効な最後の照度を保持します。同じ lux が長時間届かなくても失効させません。
- ホーム・確認・時計間の切替では購読・照度・進行中の追従を維持します。時計の時間帯別輝度は、有効な照度がまだない場合だけ使います。

## 描画コントラスト（0.6.0）

`ContrastPalette.kt` にAndroid非依存の役割別パレットを置きます。有効なセンサー受信済みの場合に限り、keeperが適用した平滑化輝度から `factor = clamp((level - 0.20) / 0.20, 0, 1)` を計算します。0.20以下（20lux相当）は従来色、0.40以上（100lux相当）は明所色、その間はARGB各成分の線形補間です。照度と輝度のmappingは変更しません。係数は既存の0.02ヒステリシスと250ms/最大0.025の追従を使うので、1ステップの係数変化は最大0.125です。目標到達で予約が止まり、コントラスト専用のループはありません。最初の有効luxだけは既存どおり即時適用です。

1つのkeeperがホームと時計へ同じ係数を配信し、変化時には両Viewをinvalidateします。時計を触らなくても照度変化で再描画し、画面切替で色を戻しません。未受信・センサーなし・登録失敗時は係数0（時刻由来の0.60は明所判定に使わない）、停止時も0へ戻し、再開時には古luxを使いません。不正luxは既存どおり無視して最後の有効値を維持します。

明所でも地とカードは暗く保ち、文字・アイコン・境界を明るくします。薬はSOON/TODAYの琥珀色、LATEの赤系を維持し、primary・選択は明るいfillと暗い文字の対を維持します。disabledは従来のalpha 122/255、pressは白34/255、focusは独立色です。disabledの有効化条件・タッチ領域は変えません。

| 明所の役割 | 前景 / 背景（RGB） | 相対輝度コントラスト比 |
|---|---|---|
| 時計数字・日付 / カード | F5FFF0 / 101410 | 18.10:1 |
| 時計札文字 / 札fill | FFE8A5 / 211B0D | 14.13:1 |
| お世話文字 / fill | F6FFEF / 141D15 | 16.83:1 |
| 経過時間 / お世話fill | CEE6BE / 141D15 | 12.90:1 |
| 状態の警告行 / 注意背景 | FFB19A / 17140E | 10.51:1 |
| 確認タイトル / panel | FAFFF5 / 182219 | 16.14:1 |
| 通常ボタン文字 / fill | EEFFE2 / 202D1C | 13.79:1 |
| primary文字 / fill | 142009 / EFFFC0 | 15.91:1 |
| 選択文字 / fill | 211800 / FFE3A0 | 14.01:1 |

比率はsRGBを線形化した相対輝度での計算値で、バックライト・環境反射・アンチエイリアス込みの実測ではありません。主要な文字/fill対の補間中の単調性（8bit丸めの許容0.025）と明所7:1以上、明所のpress合成後4.5:1以上を単体テストします。薬の文字7:1以上・アイコン4.5:1以上、pulse最暗時の明所の状態文字7:1以上・境界3:1以上も検査します。

時計のゆっくりした濃淡 `ClockMath.shade`（0.86〜1）は、係数に応じて `shade + (1 - shade) * factor` として、明所で1にします。時刻・移動・450msのフリップ・札は維持します。カードに明所で91A58Aの枠を足します。フリップ中の一時的な黒shadow（最大60%）は残るため、その動く半面の数字は上表より暗くなります（最悪合成時でもカードとの比3:1以上）。disabledは文字とfillをそれぞれ背面へalpha合成するため上表のprimary比にはなりません。全係数で暗い文字の関係と1.5:1以上、有効時より弱いことを検査します。scrim・トーストの重なり、実環境での見え方は親担当の実機確認が必要です。

## 未受信・停止・再開

NaN、無限大、負の lux、空の `values` は無視し、最後の有効な値または未受信時の動作を維持します。センサーがない・登録できない場合も未受信のまま動作します。

未受信時はホーム・確認・シナリオ選択では `BRIGHTNESS_OVERRIDE_NONE`（システムの輝度）、時計では従来の現地時刻別（06–18時 **0.60**、18–22時 **0.20**、22–06時 **0.05**）です。時計の未受信時だけ分の境界＋20msに再評価し、時刻・タイムゾーン補正にも1分以内で追従します。有効な照度を受けた後は時刻で輝度を変更しません。

`onPause` または View の detach で購読・輝度の予約を止め、ウィンドウ指定を解除します。再開時は古い lux を捨てて再登録し、新しいイベントまで未受信時の動作に戻ります（通常の前面復帰は従来どおりホーム）。重複 start は登録を増やしません。セッションと予約の識別子、および Android の listener の同一性で、停止後や再開後の古いイベント・タイマーによる更新を防ぎます。

`AmbientBrightness.kt` は Android に依存しない補間・変動抑制・セッション制御、`WindowBrightnessController.kt` は Android のセンサーと Handler の接続です。古い時計専用 keeper は共通制御に統合し、`ClockBrightness` の時刻判定は未受信時に再利用します。

## 実機での確認手順（担当者が対象端末を選択して実施）

以下の `SERIAL` は導入担当者が対象を確認して指定します。端末の識別子や生ログを公開リポジトリへ保存しません。設定を変更するコマンドや権限付与は不要です。

```sh
SERIAL='<対象端末のシリアル>'
adb -s "$SERIAL" shell dumpsys sensorservice
adb -s "$SERIAL" shell settings get system screen_brightness_mode
adb -s "$SERIAL" shell settings get system screen_brightness
scripts/install.sh "$SERIAL"
adb -s "$SERIAL" logcat -v time 'HogoBrightness:D' '*:S'
# 別のターミナルで、ウィンドウ指定を見る（screenBrightness）
adb -s "$SERIAL" shell dumpsys window windows
```

1. `sensorservice` に `android.sensor.light`（type 5）があることを確認します。debug の `HogoBrightness` に `TYPE_LIGHT registered` が出ること、有効な受信後に `lux=... brightness=... contrast=...` が出ることを見ます。センサーなし・登録失敗時は `TYPE_LIGHT unavailable; fallback` です。
2. ホームでセンサー部分を手で覆い、外し、lux と指定輝度が下がってから上がることを確認します。覆う際に表示へ触れないようにします。初回以外は上記の時間をかけて変化します。暗いまま・明るいまま数十秒保ち、イベントが止まっても目標へ到達し、その後値を保持することを見ます。
3. 同じ操作を確認画面・シナリオ選択・時計でも行います。contrastが0〜1で追従し、明所でお世話・薬のSOON/TODAY/LATE、状態警告、確認の戻る/やった（ガード中disabledも含む）、シナリオの選択・focus、取消トーストの文字と枠が読めることを目視します。時計は触らずに明暗を変え、ほぼ白の数字・日付と札・枠が変化すること、分のフリップ中にも判読できることを見ます。ホーム→確認→戻る→時計→ホームで登録ログが増えず、同じ環境光では輝度の解除や時刻値への切替が起きないことを確認します。明暗の追従途中にも画面を切り替えます。
4. HOME 操作でアプリを背面にし、アプリウィンドウの指定が解除され、センサー購読が残らないことを `sensorservice` と `dumpsys window` で確認します。復帰するとホームを表示し、新しい登録ログと受信があることを見ます。背景中に明暗を変えてから復帰し、古い lux を使わないことも確認します。
5. 最初に読み取ったシステムの輝度値と自動調光モードが変わっていないこと、AndroidRuntime にこのアプリのクラッシュがないことを確認します。実際の見やすさは目視で確認します（スクリーンショットの画素からバックライト輝度は測れません）。

ログは debuggable なアプリだけで出します。適用中は最大約1秒ごとに加え、初回・目標到達・指定解除を記録し、静止した同じ値を繰り返し出しません。記録するのは登録結果、lux、指定輝度、コントラスト係数だけです。ログ間に省略した中間ステップは `dumpsys window` でも確認できます。release はこのログを出しません。
