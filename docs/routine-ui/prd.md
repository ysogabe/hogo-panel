# 猫のお世話と定期予定の統合 UI — PRD

2026-10-18 / 提案段階。画面案は [prototype.html](prototype.html)、設計は [design.md](design.md)。

## 背景と目的

日々のお世話を記録する hogo-meter と、週次・月次のお世話の予定を、一台の Echo Show 5 で確認する。ユーザーの希望は「猫のお世話に関する予定が中心」。単に予定を表示するだけでなく、通知を見て「今回実施したか」を確認できることを重視する。

現在の Hogo Panel は時計だけの Android PoC。今回は、実 API 連携に先立って画面構成・通知・実施確認・画面遷移を設計し、架空データの HTML モックで比較・操作する。Android の機能追加と Google / hogo-meter 接続は次の段階。

## 使う人と場面

家で猫のお世話をする人が、端末の前を通ったときに「今必要なこと」と「最後にやったこと」を確認し、タッチで記録する。毎回のごはん等は hogo-meter、週次の給水器洗浄や月次の在庫確認等は定期予定として扱う。具体的な周期・手順は利用者が設定する。サンプルは飼育・医療上の推奨頻度ではない。

## ゴールと今回扱わないこと

- ホームを一目見るだけで、期限を過ぎた予定・今日の予定・直近のお世話記録が分かる。
- 通知から詳細へ進み、その回だけを完了・再通知・見送りできる。
- 週次・月次・完了履歴と低輝度時計の関係を決める。
- 今回は実アカウント、本番記録、Google OAuth、バックグラウンド通知、音、実機輝度の制御を実装しない。公開モックの操作は架空のデータをメモリ内で変更するだけ。
- カレンダー編集アプリは作らない。将来の予定の登録・周期変更は Google 等の元サービスで行う想定。端末には閲覧・実施確認・再通知を中心に置く。

## 要求

- **R1 必須:** 960×480 の横画面で、ホーム左に定期予定、右に日々のお世話を同時表示する。猫の名前は架空の「こむぎ」とする。
- **R2 必須:** 予定には対象日・時間・週次/月次・未実施/実施済み/見送りを表示する。通知時刻と期限を区別し、期限超過と再通知待ちは同時に表示できる補助状態とする。色だけに依存しない。
- **R3 必須:** 「今回」の予定の詳細に、対象日、繰り返し、実施状態、通知時刻、期限、保存先を明記し、「今回実施した」「あとで知らせる」「今回は見送る」を選べる。再通知は通知時刻を過ぎた未実施の回に限定する。完了記録は対象日当日から可能とし、当日の時刻前は前倒しと明記する。
- **R4 必須:** 完了しても次回の予定は完了にならない。完了取消は履歴から可能。見送りは完了件数へ含めない。古い未実施は自動完了・自動見送りにせず、同じ系列はホームでまとめ、一覧で各回を確認できる。
- **R5 必須:** 週次・月次の一覧と、当月に実施・見送りを記録した履歴を確認できる。ホームは未完了の優先事項を表示し、全件は一覧へ案内する。
- **R6 必須:** 通知は対象時刻の到達を契機とする。再通知は元の予定日を変えず、1時間後等の別の通知時刻を設定する。閉じるだけで完了扱いにしない。
- **R7 必須:** 待機時計からの最初のタッチは復帰専用。予定通知を待機中に受けても記録操作へ直接つなげない。通知と通常の時計仕様の優先関係を説明する。
- **R8 必須:** hogo-meter のカードでは、最終記録・経過時間と、新しいお世話の記録を確認する。定期予定の完了とは独立し、相互に自動で記録しない。
- **R9 必須:** Google Calendar / Tasks / hogo-meter はモックと明示する。公開モックに実データ、認証情報、端末識別子を含めず、外部通信も行わない。
- **R10 必須:** 通信失敗・古い状態・初回データなし・一覧に未完了なしを区別する設計にする。オフライン状態の例を画面で確認できる。
- **R11 必須:** 週次・月次の予定の取得元を将来差し替えられるよう、予定そのものと実施状態を分ける。Google 固有の制約と、今回のモックが省略する動作を明記する。
- **R12 あると良い:** 夜間の控えめな通知、対象カレンダーと猫の選択、端末以外からの完了共有について、次の設計判断を残す。

## 受け入れ条件

- **AC1（R1, R2）:** 初期ホームで定期予定2件と日々のお世話3項目を同時に確認でき、週次と月次・期限超過の文字がある。
- **AC2（R3, R4）:** 予定を開いて完了すると、その回がホームから消えて履歴へ移る。履歴から取消すると未完了に戻る。同じ系列の別の回を変更しない。
- **AC3（R2, R3, R6）:** 再通知を選ぶと、予定の元時刻と期限超過表示を保ったまま「再通知 11:30」等を表示する。通知時刻前には再通知できない。見送りは履歴へ移るが実施済み件数に含まれない。詳細で通知と期限を確認できる。
- **AC4（R5）:** 週次と月次のフィルタで対応する予定だけを表示する。履歴の実施済みと見送りを区別でき、空状態にも説明がある。
- **AC5（R6, R7）:** 通知画面を閉じても未完了が残る。待機通知または時計を1回触っても、実施・お世話記録が増えず、次の操作で詳細確認する。
- **AC6（R8）:** お世話カードを押すと対象項目の記録確認が出る。確認後にその項目の最終記録のみ変わり、定期予定は変わらない。
- **AC7（R9, R10）:** 「架空データ」「リロードで初期化」が表示される。オフライン例では状態が古いこと、予定はこの端末への保存、お世話は送信できないことが分かる。
- **AC8（R11, R12）:** 設計書に取得元と完了状態の分離、発生回の識別、月末・終日予定・時刻変更・削除・夜間・複数端末の扱いがある。
- **AC9（R1〜R11）:** HTML プレビューで構文・実行時エラーと960×480枠のはみ出しがないことを確認し、通知3件・複数の未実施回・日々のお世話4項目以上もブラウザで確認する。Android 実装の検証と区別して結果を残す。

## 制約

Android 11 / API 30、960×480、32ビット ARM、約1GB RAMの常設端末。既存時計は維持する。文字と操作対象は端末上で確認する必要があり、今回の縮小ブラウザプレビューは実機のタップしやすさ・輝度の証明にはしない。全てのサンプル予定と記録は架空。

## 決まっていないこと

実際の予定・周期・対象の猫、音の有無、夜間時間帯、Google取得元、完了の家族共有先。まず UI の方針をレビューし、その後に Android の mock 実装、hogo-meter と Google の実連携の順に進める。
