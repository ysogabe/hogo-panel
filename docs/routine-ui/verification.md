# 画面案の確認記録

2026-10-18。対象は [HTML モック](prototype.html)。実機の Android アプリや実サービス連携の検証ではない。

## 確認結果

- インライン JavaScript を抽出し `node --check` で構文確認した。
- T3 の `html_preview` で幅960・728・360の描画を確認。コンソールに実行時エラーなし。360では端末画面を縮小するため、実機の文字サイズの評価には使わない。
- T3 の共同ブラウザで、実際に描画された DOM のボタンを操作し、次の15項目を確認した。

1. 初期ホームに定期予定2件・日々のお世話3項目がある。
2. 予定カードから詳細が開く。
3. 今回の完了で次回は完了にならない。
4. 実施済みの回が履歴に表示される。
5. 履歴から取消できる。
6. 週次の一覧に週次だけが表示される。
7. 再通知で元の予定時刻が変わらない。
8. 見送りを実施済み件数へ含めない。
9. 待機通知からの復帰で記録・実施が増えない。
10. 時計からの復帰はホームへ戻るだけ。
11. 日々のお世話の記録で定期予定は変わらない。
12. 日々のお世話の直前の記録を取り消せる。
13. オフライン例で日々のお世話の記録を送信できない。
14. オフライン例でも予定の実施状態は端末側で変更できる。
15. 初回取得前を「未完了なし」と区別する。

月次のページ送りで対象日順に次の2件へ移ること、今日の予定の完了後に「今日の次の予定」から消えることも追加確認した。

ホーム・週次・月次・通知・履歴・設定について、主な操作対象が960×480の論理枠からはみ出していないことを DOM の矩形で確認した。予定詳細・お世話記録確認のモーダルも同じ枠内に収まった。外部宛てのリソース要求はなかった。

## 対応する受け入れ条件

AC1〜AC7とAC9のモックで再現した範囲を確認。AC8は設計レビューで確認する。タイマー・バックグラウンド通知・音・実機の指のジェスチャー・輝度・持続保存・実 API は未検証。モックの時刻は固定で、リロード時に初期化する。

## 初回レビューと修正

Opus による設計レビューは必須3件、安全面レビューは必須0件だった。必須は全て採用した。

- 通知3件時のはみ出し: 予定・通知・履歴・日々のお世話一覧を1ページ2件にし、ページ送りは高さ60pxにした。
- 時刻前の再通知: 通知時刻前は「あとで」を出さず、処理側にも条件を付けた。未来日の完了は対象日からとし、当日の時刻前は前倒しを明示する。
- 未実施の蓄積: 自動見送りせず保存し、ホーム・通知は最新回と以前の未確認件数、一覧は各回を表示する。自動通知の上限と翌朝への繰り越しを明文化した。

推奨・参考から、期限と通知の分離、期限超過と再通知の併記、今日以前だけのホーム、通知時刻の明記、閉じる文言、画面遷移図、可変数のお世話一覧、保存先の比較、通信失敗と鮮度、月表示、見送りの色、猫と予定の対応、時計境界タッチ等を反映した。

安全面の推奨から、未知件数の「—」、見送りの60px対象、時計切替時のトースト消去、8秒の取消期限と結果表示、取消時の版確認、取得calendarIdとアカウントデータの分離を反映した。将来の夜間の実効再通知時刻、予定本文をログへ残さないこと、認可経路の実機確認も追加した。医療に関する推奨はモックの架空データ表記の整合だけを採用した。医療アラームの設計は今回の範囲に加えていない。

修正後、ブラウザで安全面5項目（未知件数、見送りの大きさ、取消結果、時計切替、8秒期限）と設計13項目（時刻前の再通知制限、未来日の完了制限、ホームの対象、期限超過併記、未確認集約と保存、可変数のお世話、通知3件の2ページ表示とページ送り）を追加確認した。構文確認とHTMLプレビューも成功した。

## 第2ラウンドと追加修正

前回の必須3件と安全面の修正は解消と評価された。新たに「最新回を完了すると古い回が同じ通知へ繰り上がる」が必須1件として指摘されたため採用した。系列の代表を、状態を問わない今日までの最新回に固定した。代表を完了・見送りにしても古い未実施は通知へ戻さず、「以前n回未確認」という一覧への別リンクから確認する。古い記録自体は保存する。

併せて取消・すべてリンクの60px対象、種類数と回数、出しきれない件数、待機通知の未知件数、以前の未確認の詳細への補足、夜間に重なる2回目の通知、HTMLの文字列エスケープを反映した。ブラウザで代表の完了・見送り・取消と古い回の保持等10項目を確認し、空の一覧・履歴・通知、通知3件の両ページ、5項目のお世話一覧を含む14場面の配置と、2つの確認モーダルが枠内に収まることも確認した。

## 最終確認（第3ラウンド）

Opus が状態ロジックを Node で実行し、最新回の完了・見送り・取消、古い未確認の保持、全系列完了時の空状態を確認した。必須0件、設計段階として承認可。推奨1件「古い回にも再通知を約束する」は採用し、表示条件と処理側を代表回だけに限定した。古い回の明示的再通知も行わない、と設計書へ追記した。変更後、古い回のボタン非表示・処理側の拒否・代表回のみ設定可能と、古い回が通知へ戻らないことをブラウザで再確認した。

設計レビューは全3ラウンド、安全面の初回レビューは別タスク1回。初回必須3件と第2ラウンドの必須1件を解消した。実機・Google・hogo-meterの実接続とAndroid機能追加は今回実施していない。
