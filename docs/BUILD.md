# ビルドと端末導入

Hogo Panel（applicationId `io.github.ysogabe.hogo.panel`）のビルドと導入の手順です。0.1.0 は時計だけの PoC、0.2.0（versionCode 2）は架空データだけの操作モック（アプリ表示名 Hogo Panel Mock）、0.2.1（versionCode 3）はそれに当日・未確認の薬カードの明滅を足したもの、0.2.2（versionCode 4）は時計の輝度を現地時刻で日中0.60・夜0.20・深夜0.05に切り替えるもの、0.2.3（versionCode 5）は時計を約1.3倍（814×281）にして直下に日付と曜日を同じ幅で出すものです。0.3.0（versionCode 6）は、操作モックに Mock API から投薬予定を取る評価用の API モードを足したものです（debug ビルドだけ。[下記](#api-モードdebug-だけ)）。導入手順は同じで、上書きインストールできます。

## 必要なもの

- JDK 17
- Android SDK（compileSdk 35）。`ANDROID_HOME` を設定するか、リポジトリ直下の `local.properties` に `sdk.dir=<SDK のパス>` を書く（`local.properties` は Git 管理外）。
- 導入時のみ `adb`（platform-tools）。
- 採用バージョン: Gradle 8.11.1（wrapper）、Android Gradle Plugin 8.7.3、Kotlin 2.1.0、minSdk 30。

## ビルドと検証

```sh
./gradlew testDebugUnitTest assembleDebug lintDebug
```

- 時刻境界（`09:59 → 10:00`、`23:59 → 00:00`）、時刻・タイムゾーン補正、フリップする桁の判定、移動範囲などの時計の単体テスト（16件）に加えて、操作モックの単体テスト（2暦日前の判定と月・年・うるう日の境界、別の回の識別、記録・取消の独立性、450msの誤記録防止、時計復帰のジェスチャー消費、切替境界、マルチタッチ、ライフサイクル、レイアウトの枠内収まり）を実行します。0.2.1では明滅の対象・周期・開始停止の9件も加え、合計101件です。0.2.2では輝度の時間帯の境界・日跨ぎ・タイムゾーン・時刻補正と、予約の開始・停止・二重予約・停止後コールバックの9件を加え、合計110件です。0.2.3では日付の暦年・曜日・日跨ぎの2件を追加し、合計112件です。0.3.0では API モード（応答の検証 `MedicationsJson`・接続設定 `ApiConfig`・状態遷移・取得の予約と同時1件・日付またぎ・押している間の保留など）の173件を足し、合計285件です。
- Mock API の単体テスト（Python 標準の `unittest`、120件）は別に実行します（Android のビルドとは独立）。

  ```sh
  cd tools/mock-hogo-meter && PYTHONDONTWRITEBYTECODE=1 python3 -m unittest
  ```

- debug APK は `app/build/outputs/apk/debug/app-debug.apk` に出力されます。APK とビルド出力はコミットしません。
- lint は警告のみで失敗しません（ランチャーアイコン未設定など）。操作モックの追加後もエラー0件で、警告は既存の3件（アイコン未設定、Android 12以降のバックアップ設定、向き固定）です。

## release APK の検査（通信を持たないことの確認）

投薬予定の取得（API モード）に使う `INTERNET` 権限と、127.0.0.1 だけに平文を許す network security config は `app/src/debug` にだけ置きます。release の APK にそれらが入っていないことを、ビルドのたびに確かめます。

```sh
./gradlew assembleRelease     # 署名設定は無いので app-release-unsigned.apk ができる（導入はしない。検査だけ）
APK=app/build/outputs/apk/release/app-release-unsigned.apk

# aapt2（build-tools）で、権限と属性がマニフェストに無いこと
aapt2 dump permissions "$APK"                                          # package: の行だけで、uses-permission が出ない
aapt2 dump xmltree --file AndroidManifest.xml "$APK" \
  | grep -n "uses-permission\|networkSecurityConfig\|usesCleartextTraffic"   # 何も出ない（grep は終了コード 1）
aapt2 dump resources "$APK" | grep -i "xml/\|network"                  # 何も出ない（network_security_config が無い）

# apkanalyzer（cmdline-tools）でも同じ
apkanalyzer manifest print "$APK" | grep -n "uses-permission\|networkSecurityConfig\|usesCleartextTraffic"   # 何も出ない
```

- 比べるときは `app/build/outputs/apk/debug/app-debug.apk` に同じコマンドを実行します。debug だけに `android.permission.INTERNET` と `networkSecurityConfig`（`res/xml/network_security_config.xml`）が出ます。
- debug の network security config は、`127.0.0.1`（`includeSubdomains="false"`）だけに平文の HTTP を許し、それ以外は既定（禁止）です。`aapt2 dump xmltree --file res/xml/network_security_config.xml app/build/outputs/apk/debug/app-debug.apk` で中身を確かめられます。
- 0.3.0 の release APK（`app-release-unsigned.apk`、versionCode 6）で、上の検査が通ることを確かめました（`uses-permission`・`networkSecurityConfig`・`usesCleartextTraffic`・`xml/` のリソースが無い）。
- release には通信の許可が無いので、接続設定ファイルがあっても取得は `NETWORK` の失敗になるはずです（release は `run-as` も使えないので、設定を置く経路自体がありません）。ここは仕組みからの推論で、実機では確かめていません。

## API モード（debug だけ）

アプリのデータ領域に接続設定（`files/api-config.json`）があるときだけ、パネルは 127.0.0.1 の Mock API から投薬予定を取ります（API モード）。無ければ今までのシナリオ選択の操作モックのままです。設定は `tools/mock-hogo-meter/push-config.sh` が `adb shell run-as` で置き、`am force-stop` の後に起動し直して反映します。手順・形式・安全面は [docs/calendar-mock/design.md](calendar-mock/design.md) と `tools/mock-hogo-meter/README.md` を参照してください。API モードではシナリオ選択（ヘッダーの長押し）は使えません。

## 端末への導入

```sh
adb devices -l                       # 対象端末のシリアルを確認する
scripts/install.sh <serial>          # 上書きインストールして起動する
```

- シリアルは必須です。省略すると何もせず終了します。複数台が接続されていても、指定した 1 台にしか操作しません。
- `scripts/install.sh` は `adb -s <serial> install -r` と `am start` だけを行います。HOME 指定、権限の付与、設定の変更はしません。
- 手動で行う場合は `adb -s <serial> install -r app/build/outputs/apk/debug/app-debug.apk` の後に `adb -s <serial> shell am start -n io.github.ysogabe.hogo.panel/.MainActivity`。

## Wi-Fi デバッグ（ワイヤレス ADB）

今回の端末は既に TCP ADB が有効で、`adb connect <端末のアドレス>:5555` による接続を確認しました。`adb devices -l` に出るシリアル（`<アドレス>:<ポート>` 形式）を `scripts/install.sh` へ渡せます。TCP ADB の設定変更は行っていません。再起動後の継続性は未検証です。

Android 11 のペアリング式「ワイヤレス デバッグ」は今回無効で、検証していません。これを使用する別の端末では、端末側で表示されるペアリング用アドレスに `adb pair` し、接続用アドレスに `adb connect` します。アドレスやペアリングコードは端末固有の情報なので、公開リポジトリ・ログ・Issue に残さないでください。

## 操作モックの試し方（0.2.0）

導入して起動すると、通常のお世話（ごはん・トイレ・目薬）だけが出ます。薬の画面は、ヘッダー（猫の名前「こむぎ」や現在時刻の付近。時計ボタンの上は除く）を約0.7秒長押しして開く「モック：シナリオ選択」から再現します。

| 項目 | 状態 |
|---|---|
| 普段 | 予定日の3日前。薬は出ない。起動時の既定 |
| 2日前 | 薬カード2枚（フィラリア・フロントライン）が左、お世話が右。琥珀色の「そろそろ」 |
| 当日 | 同じ配置で「今日」 |
| 過ぎたら | 赤系の「未確認」 |
| 実施後 | 両方記録済みの状態。普段の3列 |
| 時計 | 2日前の状態で、低輝度の時計と薬名の札を表示。触れるとホームへ戻る |
| リセット | 全ての記録・取消・経過時間を初期値へ |
| 閉じる | 何も変えずに閉じる（戻るキーも同じ） |

ホームの時計ボタン、または3分の無操作でも時計になります。時計の最初のタッチは、全ての指が離れるまで消費してホームへ戻るだけです。シナリオの日付は固定の架空日で、ヘッダーの時刻と時計だけが実時間です。状態はメモリ内にあり、プロセスの再起動で初期化されます。

### 時計の輝度の試し方（0.2.2）

時計中のウィンドウ輝度は現地時刻で 06:00–18:00＝0.60、18:00–22:00＝0.20、22:00–06:00＝0.05 です（端末の現在の壁時計とタイムゾーン。モックの日付は無関係）。時計ボタンか3分の無操作で時計に入り、現在の時間帯の明るさで表示されることを見ます。時計を出したまま時間帯の境目を越えても自動で変わります。ホームへ戻る・背面にするとウィンドウの輝度指定は解除されます。`dumpsys window` の `screenBrightness` で指定値を確認できます。夜の0.20と解除・再適用は実機確認済み、全時間帯と境界は単体テストで確認済みです。指定値はバックライトの実測値ではなく、スクリーンショットの画素からも測れません。

### 明滅の試し方（0.2.1）

「当日」「過ぎたら」を選ぶと、薬カードの背景と枠が約2.4秒でゆっくり明暗します（文字は変わらない）。「2日前」「実施後」「時計」は静止です。確認を開くと止まり、戻る・取消で再開、「やった」で記録した薬は消えて動きも止まります。実機での確認は未実施で、親が行います。

## 表示の確認項目

現行の0.2.3は、起動直後も前面復帰もホーム（通常のお世話）です。時計は、ホームの時計ボタンか3分の無操作で入って確認します。

- 起動直後と、背面から前面へ戻った直後は、時計ではなくホームが出ること（時計に入っていた場合も同様）。
- 時計ボタンを押すか3分触れずにおくと、黒背景で横画面全体に `HH:mm`（24 時間）の低輝度の時計が出ること（0.2.3 で約1.3倍）。時刻の直下に `2026/10/19（月）` 形式の日付が時計と同じ幅で出て、その下に薬名の札（2日前などの警告のシナリオ）が添えられます。秒・ロゴ・案内は出ません。日付の左右端と時刻の左右端が揃い、札と重複せず収まることを実機画像で確認済みです。移動全範囲の収まりと日跨ぎは単体テストで確認し、実時刻の0時通過は未確認です（[0.2.3の検証記録](routine-ui/verification.md#時計の拡大と日付曜日023)）。
- 時計の中で、分が変わったとき、変わった桁だけがフリップすること。
- 時計が時間をかけて画面内を動き、端から欠けないこと。
- 時計の最初のタッチはホームへ戻るだけで、その下のボタンは押されないこと。
- 時計の間は画面が点灯し続け、輝度が時間帯のウィンドウ指定（日中0.60・夜0.20・深夜0.05。0.2.1までは固定0.05）になること（実際のバックライト輝度は目視で確認する）。ホームでは輝度の指定が解除されること。
- 時計中に背面にしたとき描画が止まり、前面復帰時はホームに合うこと。

0.1.0（時計のみ）は、起動直後から時計が出て、前面復帰時も現在時刻の時計に即時に合う動作でした。その実測は下の「実機検証結果（2026-10-18）」にそのまま残しています。
